Findings

    

    

      

        
+1.8

        
10 epochs is too short

        
The official script stops while validation is still rising. With 20 epochs, test ROC-AUC goes from 0.776 to 0.794, and the gap to the paper's Base (0.815) shrinks from 3.9 to 2.1 points.

        
Draft PR #7 · official script, unmodified

Time goes into the row encoder

        

          
        

        
row encoder 53%backward 33%GNN 11%sampling, other 3%

        
Sampling is only 1% of an epoch. The cost is dense matrix multiplication on ~71,000 sampled rows per batch.

        
PR #5 · driver-dnf, one epoch, 4 CPU cores

      

      

        
2.5×

        
Encode each row once

        
A batch holds ~71,000 sampled rows but only ~22,600 distinct ones (a race appears 33× on average). Encoding distinct rows once makes a run 2.5× faster with the same validation score (0.787 vs 0.782).

        
PR #5 · --dedup-encoder, off by default

      

      

        
5 / 22

        
Columns with missing values stop learning

        
In PyTorch Frame 0.3.0 a missing value gives its column's weights a NaN gradient; after the first step results.position, rank, fastestLap, milliseconds and number encode to 0. Fixing it changes nothing measurable on driver-top3 (0.783 vs 0.780).

        
Issue #6 · PR #8 · --nan-safe-numerical

      

      

        
3 of 9

        
Tables the model never sees

        
circuits, constructor_results and constructor_standings are 3 hops from drivers; a 2-layer GNN samples none of their rows. This is the paper's "semantic fragmentation" in miniature.

Sampling is mostly fixed

        
Only 7–8% of targets have more eligible rows than the fan-out of 128, and hop 2 never needs sampling (every row has one race). Over 90% of targets see the same subgraph in every epoch.
